# Цикл Тори

Статичне щотижневе видання: Astro 7, Markdown, локальні WebP-зображення. Берешит опублікований; наступні матеріали готуються. Посилання на місце читання ведуть на відповідний розділ українського перекладу Bible.com.

Актуальне оформлення та правила додавання глав збережено в [docs/PROJECT_SETTINGS.md](docs/PROJECT_SETTINGS.md). Усі глави й роки використовують спільний шаблон сторінки, компоненти та стилі. Інструкції для подальшої роботи агентів — у [AGENTS.md](AGENTS.md).

## Запуск

Потрібен Node.js 24 та npm.

```sh
npm ci
npm run dev
```

Відкрийте адресу, яку покаже Astro, зазвичай http://localhost:4321.

```sh
npm run check
npm test
npm run build
npm run preview
```

`dist/` — повністю статична версія. React, backend, CDN-скрипти та зовнішні запити для відображення сайту не потрібні. Шрифти зберігаються локально. Для перегляду готової версії потрібен HTTP-сервер; не відкривайте `dist/index.html` через `file://`.

## Публікація на GitHub Pages

1. Створіть репозиторій `torah-cycle` на GitHub.
2. Завантажте вміст цієї папки до кореня репозиторію. Включіть приховану папку `.github/`, файли `.gitignore` і lockfile. Не завантажуйте `node_modules/`, `.astro/` та `dist/`.
3. Основна гілка має називатися `main`.
4. Відкрийте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
5. Push у `main` або **Actions → Publish Torah Cycle → Run workflow** запускає збірку та публікацію.
6. Готова адреса з’явиться в Pages і в результаті workflow: `https://USERNAME.github.io/torah-cycle/`.

`astro.config.mjs` сам визначає `site` та `base` з `GITHUB_REPOSITORY`. Для репозиторію `USERNAME.github.io` шлях буде `/`. Для іншої назви репозиторію всі внутрішні URL, зображення, canonical, robots і sitemap отримають відповідний префікс. У локальній збірці використовується `https://example.com`: вона призначена для перевірки, а не публікації SEO-адрес.

Зовнішнього репозиторію або живого GitHub Pages deployment цей ZIP сам не створює.

## Щотижневе оновлення

1. Скопіюйте `src/content/parashot/_template.md` до `src/content/parashot/5787/SLUG.md`. Підкреслення у назві означає шаблон: він не входить до колекції.
2. Заповніть metadata та текст за [збереженими правилами](docs/PROJECT_SETTINGS.md), включно з коротким `shareDescription` для прев’ю посилання. Усі дати беріть із перевіреного календаря для діаспори (Львів), а не обчислюйте послідовним додаванням 7 днів.
3. Додайте **одне** зображення: `public/images/parashot/5787/SLUG/cover.webp`. Рекомендація: 1800×1200, 200–700 KB. Обов’язкова назва файлу — `cover.webp`.
4. Вкажіть зрозумілий `heroAlt`, `published: true`, `draft: false`.
5. Commit і push у `main`.

Збірка автоматично створить сторінку, архівний запис, попередню/наступну навігацію, responsive-копії 640/960 px та картку OpenGraph `share-v2.jpg` 1200×630 із золотою емблемою та шрифтом Source Serif 4. Шлях картинки не повинен містити префікс репозиторію: його додасть сайт.

У GitHub можна редагувати `.md` через олівець або Add file → Create new file, а фото завантажити через Add file → Upload files. Назву нового файлу починайте з `5787/…` усередині папки `parashot`, якщо папка року ще не існує.

## Metadata

- `cycleYear`: рік **початку циклу**, наприклад 5787. Це редакційний ідентифікатор циклу: остання глава може читатися вже після наступного Рош га-Шана.
- `bookOrder`: 1–5; `parashaOrder`: номер глави у книзі, 1–12.
- `gregorianDate`: явна дата читання, `YYYY-MM-DD` (зазвичай субота).
- `hebrewDate`: перевірений текст єврейської дати.
- `activeFrom`: необов’язкова дата початку показу на головній для особливих календарних випадків.
- `reflectionQuestions`: від одного до трьох питань.
- `published: false` або `draft: true` виключає матеріал зі сторінок, архіву, sitemap і вибору актуальної глави. Чернетки доступні у вихідному репозиторії, якщо він публічний: це не механізм секретності.
- Один `slug` не може повторюватися у межах одного циклу. Збірка зупиниться з поясненням при невалідних metadata або відсутньому зображенні.

## Як працює головна

Часовий пояс: `Europe/Kyiv`. За замовчуванням глава стає актуальною в неділю перед датою читання й лишається актуальною до кінця суботи. Так, 4–10 жовтня 2026 показується Берешит, 11–17 жовтня — Ноах. Це правило тижня для видання; сайт не обчислює час заходу сонця або початок шабату.

Якщо матеріалу для поточного тижня немає, головна показує останній опублікований матеріал із минулою датою. До початку першого циклу — перший доступний. Для тижня зі святом або подвійною главою задайте явні metadata: окремий об’єднаний матеріал та, за потреби, `activeFrom`. Автоматичної календарної синхронізації немає.

**Важливо для статичного сайту:** дата перевіряється під час build. У workflow вже є щоденна перебудова о 21:05 і 22:05 UTC — обидві години забезпечують перехід дати в Києві в літній та зимовий час. Окремий push не потрібний. GitHub може затримати запуск за розкладом; після тривалого періоду без комітів у публічному репозиторії scheduled workflow може бути вимкнено GitHub. Перевіряйте його стан в Actions; Run workflow або звичайний push повторно збирає головну. Не обіцяємо перемикання секунду в секунду.

## Наступний рік

Створіть `src/content/parashot/5788/` і відповідну папку фото. Повторення `slug` у **різних** роках дозволено. Архів покаже вибір року, коли існуватиме хоча б один опублікований матеріал другого циклу.

- `/parasha/bereshit/` — матеріал найновішого опублікованого циклу.
- `/cycle/5787/parasha/bereshit/` — постійна адреса конкретного року.
- `/` — поточний матеріал за датою, незалежно від того, чи вже підготовлено наступний рік.

Для найновішого циклу сторінка року має canonical на коротку адресу. Коли починається новий цикл, попередня річна сторінка стає власною canonical. Для довготривалого поширення матеріалу певного року використовуйте річну адресу.

## Власний домен

У **Settings → Secrets and variables → Actions → Variables** створіть `SITE_URL`, наприклад `https://torah.example`. `SITE_BASE` залиште порожнім (буде `/`). У **Settings → Pages → Custom domain** налаштуйте той самий домен, DNS та HTTPS. Build автоматично створить `CNAME`. Для повернення до стандартної GitHub-адреси видаліть змінну `SITE_URL` і custom domain у Pages.

## Візуал і доступність

Темна композиція зі скляною карткою; Manrope / Source Serif 4 / Noto Serif Hebrew. Іврит має `lang="he"` та `dir="rtl"`. Архів — native modal dialog: background inert, фокус лишається в діалозі, Esc закриває, після закриття фокус повертається. Книги — accordion; розгорнута одна книга. Картка адаптована для мобільних, планшетів і 4K. Читання відкривається текстовим посиланням «Читати далі». Підтримуються клавіатура, skip-link, visible focus і reduced motion; золотий перелив виконується один раз за наведення, а частинка курсора має шлейф.

Початкові зображення створені для цього проєкту генеративним інструментом. Ліцензії шрифтів: у встановлених пакетах `@fontsource` та `scripts/fonts/`. Фото для нових матеріалів додавайте із правом використання.
